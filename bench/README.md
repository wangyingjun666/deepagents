# 压测（Locust）

量两件事：接口本身的响应，以及**一次深度搜索从提交到出结果要多久**。

## 为什么不能只压 `/api/task`

`POST /api/task` 是提交即返回：请求只把任务丢进后台，立刻回一个 `thread_id`，
真正的工作在图里异步跑。所以它只有几十毫秒，压它等于什么都没压。

用户感知的时延是「提交 → 拿到最终结果」，所以 `locustfile.py` 里每个虚拟用户会
提交任务并轮询 `/api/trace/{thread_id}` 直到出现 `task_result` / `error`，把这段
总耗时单独记成 `TASK / deep_search_e2e` 一行。Locust 报表里会同时有：

| 报表行 | 看什么 |
|---|---|
| `POST /api/task` | Web 层响应，亚秒级 |
| `TASK deep_search_e2e` | **端到端任务时延，P95 主要看这行** |
| `GET /api/trace/[id]` | 轮询开销，合并成一行，确认它没喧宾夺主 |

## 为什么配 `serve_stub.py` 用

真实链路一次深度搜索要调十几次大模型，端到端耗时基本被对面推理服务主导，压出来的
P95 反映的是那台机器当时的快慢。`serve_stub.py` 把模型换成**固定延迟的桩**，
于是剩下的就都是本项目自己的开销：并发闸门排队、上下文绑定、沙箱申请回收、图调度、
事件总线落盘与扇出、WebSocket 推送。

```bash
python bench/serve_stub.py --port 8011 --model-latency-ms 300   # 桩模型 300ms
locust -f bench/locustfile.py --headless -u 8 -r 8 -t 40s --host http://127.0.0.1:8011
```

要压真实服务就换成 `python main.py` + `--host http://127.0.0.1:8000`，此时
端到端 P95 会把真实模型耗时一起算进去。

## 实测结果（8 核 CPU，进程级沙箱，模型为固定延迟桩）

轮询间隔 50ms，避免轮询本身虚增时延。

**模型延迟 300ms（近似一次真实调用）：**

| 并发 | 完成 | 失败 | 吞吐/s | P50(ms) | P95(ms) | P99(ms) |
|---|---|---|---|---|---|---|
| 1 | 60 | 0 | 1.53 | 650 | 690 | 720 |
| 2 | 116 | 0 | 2.95 | 670 | 720 | 740 |
| 4 | 213 | 0 | 5.44 | 720 | 810 | 860 |
| 8 | 222 | 0 | 5.66 | 1400 | 1500 | 1600 |
| 12 | 220 | 0 | 5.61 | 2100 | 2200 | 2300 |
| 16 | 219 | 0 | 5.59 | 2800 | 3000 | 3200 |

**模型延迟 0ms（隔离出系统自身开销）：**

| 并发 | 吞吐/s | P50(ms) | P95(ms) |
|---|---|---|---|
| 1 | 2.43 | 410 | 430 |
| 2 | 4.54 | 440 | 500 |
| 4 | 6.70 | 590 | 700 |
| 8 | 6.76 | 1200 | 1400 |
| 16 | 6.56 | 2500 | 2700 |

要点：并发 1→4 吞吐接近线性（1.53→5.44），**到 8 之后卡在 ~5.6/s 不再涨**，
再往上只涨时延不涨吞吐——这是 `MAX_CONCURRENT_SESSIONS=8` 在起作用，超出部分排队
而不是失败（全程 0 失败，30s 排队超时一次没触发）。服务端 `/api/metrics` 里的
`session:queue` 也印证了这点：325 次排队、平均等 954ms、P95 等 1329ms、拒绝 0 次。

模型延迟从 0 加到 300ms，吞吐只从 6.76/s 降到 5.66/s，说明**瓶颈在编排与 IO，
不在模型等待**。单会话下系统自身开销约 410ms（P50）。

## 已知限制

- 桩模型是单轮返回，不会触发子 Agent 委派和多轮工具调用，真实深度搜索的步数远多于
  这里，实际时延会明显高于上表。
- 压测时关闭了持久化 checkpointer（见下），所以**不含 checkpoint 落盘开销**。
- 本机 Docker 未运行，沙箱走的是进程级后端；容器后端的启动开销更高。
- Locust 本身也占 CPU，与 8 核的服务端抢资源，并发越高这项干扰越大。
